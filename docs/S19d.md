# S19d: durable live-read control

locator_read now uses the shared Sources durable operation wrapper. The operation
covers live hashing, immutable extraction and final freshness checks. Public
operation_get/operation_cancel, parent correlation, deadlines and terminal retry
semantics apply. Nested reader key order and escaped strings normalize; requests
cannot hide different selectors behind the same operation identifier. Nested
operation controls remain refused so cancellation belongs to the outer request.

Exact saved retry is historical observation/evidence at observed_at_ms and works
without the original/root. A new operation identifier triggers a new live check.
Success, cancellation and deadline failures are saved; no evidence is returned
when cancellation or freshness validation fails. The persisted per-result bound
allows4096 bytes above2MiB for live-read wrapping; aggregate32MiB reservations and
existing native-worker/cache limits remain independently bounded.

Focused tests verify normalized success retries offline after live changes,
selector conflict, actual public cancellation during extraction, terminal status,
exact cancelled/deadline retry and continued ordinary live verification. Existing
request-control and durable-operation suites remain required. Other modalities,
process-death freshness races, continuous watching and index invalidation remain
open. This does not complete Sources or C05–C06.
