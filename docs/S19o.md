# S19o: observation-driven durable reindex intent

Locator reconcile/watch commits update index_pending atomically with live history.
Indexed items match owner, captured root scope and locator. Repeated changes
coalesce to one row with the latest revision; matching original bytes clear it.
The existing retained index limits bound the queue to eight times 256 rows.
Public index_pending validates evidence and observation revision in a consistent
read transaction and remains readable without a root grant.

Native tests exercise changed/missing observations, original-byte restoration,
repeated watch checkpoints and exact retry, and owner/host/root isolation while
historical candidates remain readable. A host cancellation at the last measured
precommit check verifies rollback of both live observation and pending intent.

Queue execution, fair draining/retry, missing/new-file policy, failed-item scheduling
and catch-up for old observations remain required. This is durable intent rather
than completed automatic reindexing; full Sources and C01–C14 remain open.
