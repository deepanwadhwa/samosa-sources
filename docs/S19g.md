# S19g: observed index freshness

Index jobs retain the configured root scope at capture. Root identity is checked
before/after inventory capture. Search candidates join owner/root/path-bound
committed locator observations and qualify available hashes against their own
immutable versions. Changes and missing files are visible without erasing past
literal evidence. Legacy jobs without recorded root scopes remain unobserved.

The locator result/digest and its recorded path/scope/status/revision/time are
validated before candidate publication. Sources initializes shared locator schema
before index read transactions; candidate history is read consistently with the
indexed snapshot. No current filesystem claim is inferred from a saved observation.

Native tests cover subdirectory index/root-scope mapping; unobserved, available,
changed and missing transitions; offline search; owner and host isolation; and
actual root replacement. Existing capture-race/index/locator suites remain
required. This supplies freshness evidence for the upcoming Sources-owned watcher
and reindex policy, rather than claiming continuous monitoring is complete.
