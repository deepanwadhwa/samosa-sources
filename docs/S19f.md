# S19f: index capture freshness

Text index extraction now uses the public Sources live-read wrapper after
inventory-identity-bound registration. Original bytes must still match before
extraction and file/parent/root must remain stable through the final check.
Index persists the inner immutable literal evidence, preserving evidence IDs,
selectors, coverage, integrity validation and offline historical retrieval.

A native regression calibrates host control checkpoints on a stable extraction,
then changes the actual file at the final checkpoint in an otherwise identical
isolated fixture. Changed extraction yields one failed item, zero indexed items
and no stale search candidate; stable extraction and exact offline step retries
remain readable. No production fault hook is needed. Existing index process-death,
quota, stale inventory, owner and integrity tests remain required.

This closes the capture-time freshness gap. It does not implement continuous
watching, invalidation of previously indexed items or replacement versions.
Those remain required along with broader indexing/enrichment/Chutni integration.
