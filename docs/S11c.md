# S11c — bounded live locator reconciliation after checked effects

C02/C05/C06/C10 subset. Sources owns live locator observations and immutable
content versions; Agent retains effect intent/receipts. Deliver public reconciliation
of at most eight host-local relative locators against expected immutable versions
and optional historical inode tuples. Sources independently verifies its granted
filesystem; an Agent receipt alone never proves a current location or absence.

Included: native locator.c/h, public source dispatch, owner-local locator/operation
state, native fault/identity/quota tests and public Agent/Sources effect interaction.
Use native no-follow descriptor traversal and streaming SHA verification <=1MiB
per inspected file. Root scope and caller identity belong to host config. Results
explicitly distinguish available, missing, changed, unsupported and uncertain
observations at a committed checkpoint, with no claim of continuous freshness.
Do not rewrite immutable snapshots or evidence/citations when locations change.
Reconciliation can report a foreign replacement without adopting it as the
expected version. Require actual content verification for available claims.

Bound live associations and exact retry operation results; no eviction. Same
operation with changed parameters conflicts; completed exact retry remains
historical and works without filesystem access. New operation rechecks current
files. Keep mechanical locator identity separate from immutable content identity.
Every locator/operation is owner-bound and scoped to a specific configured host
and granted root. A changed root creates a different locator scope.

Acceptance: copy/move/inverse available/missing observations, retained snapshot
reads after deletion, same-byte foreign inode replacement, modified bytes with
preserved metadata, symlink/FIFO/escape/oversize refusal, directory/file races,
owner hiding/retry conflict/offline retry and actual quota boundaries. Sources
build/test with Agent/Inference absent; public configured effect receipt consumer
uses JSON only. Mac/Linux native sanitizers and independently copied releases.
No Python. Exact focused commands will be recorded when the runner exists.

This is preparatory for full C06/C10. Automatic Agent reconciliation integration,
schedules, folder questions/organization, wider readers, fair provider admission,
App/service/auth/install and full retirement remain required. Begin implementation
after S11b2 final qualification; no legacy reader/action retirement yet.
