# S19n: atomic watch runtime admission

Runtime admission now validates the retained owner-bound registration and captured
root, then creates/acquires the private runtime lease while holding the shared
observer lease. Stop, removal and cleanup use that same lease. This closes the
identified stale-admission path that could recreate an orphan after cleanup.
Startup retries observer/store contention for at most five seconds; an already
held runtime lease remains an immediate watch_busy refusal.

Native tests pause admission while holding the observer lease both before and
after runtime lease creation. Concurrent stop refuses busy, actual SIGKILL
releases the shared lock, and subsequent stop/removal/recovery completes. After
removal and cleanup, admission refuses unknown_watch without creating a lease.
Test pauses exist only in test-fault builds. Continuous eight-worker regressions
exercise bounded startup contention alongside existing shutdown/restart checks.

This checkpoint addresses that specific admission/removal ordering race. Broad
fair scheduling, resource qualification, automatic lifecycle and reindex scheduling
remain open, as do full Sources qualification and the complete C01–C14 rebuild.
