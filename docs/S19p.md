# S19p: retained immutable reindex execution

Public index_reindex_step captures one to four pending observed text items under
the existing index lease. Registration binds the observed mechanical identity;
locator_read qualifies extraction; the extracted version must match the observed
hash. Commit rechecks the observation revision and root scope, saves a new
immutable index version and removes only the corresponding queue intent.

Historical searches retain original and reindexed evidence. Further observations
schedule against the latest version. Additional history is bounded to 256 versions
globally; combined original/reindexed text/evidence stays within 8MiB. Existing
snapshot/cache/database/operation limits also remain in force.

Native tests exercise actual SIGKILL after an item commit, competing admission,
resume with a fresh operation, exact offline retry/conflict, owner isolation,
historical freshness, stale identity and missing-file refusal, and all 256 additional
versions through public admissions. A paused worker receives a newer observation
after extraction and refuses stale_observation without committing or clearing it.
Test pauses are confined to test-fault builds.

Fair queue draining/retry, automatic execution, missing/new/failed-file policy and
legacy catch-up remain open. This adds explicit bounded execution; it does not
complete automatic indexing or full Sources/rebuild qualification.
