# S19r: bounded cross-job automatic queue step

Public index_queue_step selects one pending item across jobs matching the configured
owner and granted root scope. An exclusive index lease protects selection and
dispatch. Durable job turns order ready jobs; per-item attempt counts order work
inside the selected job. Turns persist when successful items change again, so a
continuously changing job cannot keep overtaking an older ready peer.

One schedule row per retained job bounds metadata to eight rows globally. Invalid
turns refuse; INT64_MAX refuses scheduler_limit before overflow. Automatic attempts
consume no client operation receipts. They retain the existing per-item immutable
commit/recovery guarantees rather than exact response replay.

Native two-job tests select a missing first job and then a healthy peer, preserve
historical evidence, exclude owner/host/replacement-root scopes, perform 520 failed
automatic attempts, fill all 512 client receipts and still complete automatic work.
A healthy job that changes again immediately yields to its older ready peer.
Private negative/max-turn tests check typed corruption/overflow refusal.
Existing process death, observation race, quota and integrity regressions remain.

A continuous runner, timed backoff, full missing/new/failed-file policy and legacy
catch-up remain required. This adds the bounded automatic step and durable job
ordering, not a complete automatic indexing service or full Sources release.
