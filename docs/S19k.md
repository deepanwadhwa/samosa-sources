# S19k: watch health and eight-worker qualification

Sources persists completed-attempt counts, successful/failed reports, last attempt
time and last error per retained watch. Public get exposes health alongside lease
status and checkpoint; public clients cannot write counters. Temporary/permanent
step failures retain prior checkpoints. Successful reporting clears the last error.
Checkpoint and health commits remain separate, explicitly allowing health lag if
a worker dies after committing a checkpoint.

Native process qualification admits eight watchers, requires successful reports
from every worker, stops one through the public API and checks remaining peers
stay running. It also requires a persisted scope_unavailable report after actual
root replacement. Existing signals/restart/state-replacement and registry/checkpoint
regressions remain part of normal and parent/worker sanitizer tests.

Busy registration/stop returns the existing bounded-admission refusal; the native
test retries within five seconds, matching the runtime polling retry policy.
Observed progress of all eight workers qualifies this workload, not general FIFO
fairness or absence of starvation under arbitrary load. Broader scheduling/resource
limits, removal/replacement, automatic lifecycle and reindex policy remain open.

Health retrieval validates integer types/ranges, count agreement and bounded error
identity before publishing JSON. A native owner-local corruption fixture writes a
negative failure count and requires one typed refusal without partial checkpoint.
Normal/ASan+UBSan final runtime suites qualify this behavior on both platforms.
