# S19l: bounded watch removal/replacement

Owner-bound stopped-watch removal acquires the observer writer lease and excludes
active runtime leases, then atomically clears registry/checkpoint/health metadata.
Normal cleanup unlinks the checked private runtime lease. Source snapshots,
locator history and historical indexes stay retained. Shared durable request
controls provide saved removal results after registry deletion.

Fresh watch generation identities include OS entropy so a removed/recreated
registration cannot inherit an old worker identity. Stopped runtime admission
creates no lease; late admitted workers discovering unknown_watch clean their
own checked lease before exit. Removal reports any retained lease cleanup.

Native tests qualify active/foreign/held-lease refusal, stopped removal, exact
saved offline retry, old-ID refusal, capacity recovery, same-parameters fresh
identity and immutable source readability. Registry/checkpoint and eight-worker
normal/sanitizer regressions remain required. Crash-time lease cleanup, broader
resources/fairness, automatic lifecycle and reindex scheduling remain open.

Committed removal wins a cancellation/deadline race during durable finalization:
public operation status/receipt must reflect the already-completed metadata action.
The private operation flag is set only after a successful removal core response;
ordinary readers keep their existing late-cancellation publication checks. Native
operation regression submits cancellation and an expired deadline after a marked
commit, then verifies the removed receipt persists and retries exactly.
