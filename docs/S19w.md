# S19w: immutable host upload ingestion

`sources_upload` accepts a stable host byte buffer without a root grant. It owns
a bounded copy, validates the selected format and uses the shared immutable
snapshot transaction. Its64MiB limit and shared snapshot/byte/claim quotas match
live registration; ownership is independently granted per owner. Caller mutation
after return does not alter evidence. Admission checks host cancellation/deadlines
while copying and hashing in64KiB chunks and before commit.

Normal and nonrecovering ASan+UBSan native fixtures pass macOS/Linux. They cover
foreign read refusal, independent owner claims, deduplication, quota refusal,
invalid format/UTF8/null/oversize input and cancellation. Actual64MiB text ingestion
cancels during hashing, verifies zero accepted snapshots/claims/formats, then
accepts the same bytes and reads the final range with no live root grant.

The expanded fixture also passes root-independent uploaded HTML extraction and
uploaded WAV preparation/cache reuse on both platforms, normal and nonrecovering
sanitizers. It independently decodes the prepared base64 bytes to check the
selected WAV header/payload and exact PCM. Uploaded OCR/encoded-media
integration remains separately unqualified.

The API is a host C entry point, not a completed transport/session lifecycle.
Host streaming is implemented. Durable begin/status/abort and chunk append are
implemented, with atomic snapshot publication and persisted commit retry;
fresh-process resume and two-process exact append/commit retries are qualified.
Precommit cancellation and SIGKILL rollback recovery are qualified. Broader crash
phases and broader concurrency/control qualification, service admission,
all-format upload integration and complete release qualification remain pending.
Actual64MiB public chunk staging/publication/read gates pass macOS/Linux normal
and sanitizer checks, including independent SHA256 and zero retained staging.
See contracts/uploads-v1.md for provenance and exact limits, and the architecture
verification document for terminal run evidence.

The upload fixture also covers stored and Deflate DOCX packages: it frees the
caller ZIP bytes before root-independent read_docx, checks exact selected literal
text, and checks repeated cached response equality. This qualifies the host upload
entry point, not a separate staged DOCX publication matrix.

The existing compressed-media cache fixture now has --upload mode: it ingests
fixture bytes through sources_upload with rootNULL before preparation, frees the
caller buffer, and runs the cache quota/integrity/survivor checks. --visual --upload now passes both platforms with exact blue RGBA checks,
shared audio/visual limits, distinct artifacts and cache-integrity survivors.
These sanitizer runs instrument the parent; workers and decoder libraries are
normal builds.

The PDFium fixture now uploads a100-page PDF, frees input and deletes the host
fixture before root-free read_pdf(page97), checking sentinel7319, absolute page
metadata, repeated cache response and owner refusal. OCR upload integration and
staged format-specific publication remain separate qualification requirements.

Uploaded image/PDF OCR now passes actual-engine macOS/Linux normal and component
sanitizer tests: no root grant, released input, sentinel text, cache equality,
image owner refusal and PDF page2 metadata. An earlier Linux worker-monitor
latency assertion failed once and remains unresolved broader reliability work.
