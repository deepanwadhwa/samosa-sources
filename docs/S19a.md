# S19a: bounded larger originals

Original immutable snapshots now accept up to64MiB across registration, readers
and isolated native workers. Registration allocates for the observed file size,
copies in cancellable64KiB chunks, and refuses growth or identity changes before
commit. All seven registration operations support durable operation identifiers,
parent identifiers, deadlines and exact saved retries without reopening originals.

The total snapshot quota remains128MiB; database quota160MiB; cache8MiB/128
entries. Selected text, OCR raster, document expansion, media packet, selected
window and output frame limits remain bounded independently. Larger original
limits do not enlarge DOCX expansion or guarantee every64MiB document decodes.

Native normal and ASan/UBSan checks cover4MiB+ UTF-8 text, chunk cancellation,
offline registration retry, owner refusal, exact late selected evidence,4MiB+
PCM WAV with independently checked samples at60s, cache reuse, actual64MiB text
acceptance and64MiB+1 refusal. Public visual checks use a valid4MiB MP4 with a
native-generated free box: this qualifies original transport and immutable
worker delivery, rather than dense4MiB codec complexity. The native fixture
generator's --pad mode reproduces the exact tested bytes.

Run `make test-large-sources sanitize-large-sources`; these checks are also part
of `make test` and `make sanitize`. Evidence paths and platform results are in
the root architecture verification checkpoint. Resumable uploads, live freshness
and watching, broad worst-case resources, and complete Sources release remain
open. Prior S18b archives preserve their earlier qualified1MiB snapshot.
