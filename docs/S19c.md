# S19c: live-read freshness

The public locator_read operation wraps an ordinary immutable reader in current
live-file verification. Owner-bound source/version checks precede filesystem
access. Content hash and optional device/inode constraints must match before
extraction; held descriptor metadata, relative directory bindings and root are
revalidated before evidence is returned. Derived artifacts still identify the
immutable snapshot, and historical reads remain independent of live locations.

Native focused checks cover stable selected evidence, an actual mutation between
hash verification and warm-cache retrieval, changed and missing files, foreign
owner refusal, invalid request handling, and immutable evidence after deletion.
Existing locator race/lease/root/history checks remain required. Run
make test-live-read sanitize-live-read test-locator sanitize-locator.

The wrapper supports all existing literal/OCR/media reader operations, but current
focused runtime qualification uses text. Modalities, worker death/freshness races,
continuous watching and index invalidation remain open. Public durable control
is added in S19d.
This scope does not complete C05–C06 or Sources.

Extended qualification (S19e) performs actual same-byte file, parent-directory
and root replacement during warm-cache extraction. In-flight reads refuse;
subsequent content-only reads accept stable replacements, physical tuple-pinned
reads refuse foreign inodes, and historical immutable evidence remains readable.
Normal/ASan+UBSan tests pass on macOS and Linux. This extends text-path evidence;
continuous watching and other modality races still remain required.
