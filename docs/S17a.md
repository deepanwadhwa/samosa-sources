# S17a — Sources native image/PDF OCR

Sources-only C02/C05/C06 continuation after qualified DOCX. Keep plain readers
usable with OCR engine/data absent. Reuse the native Tesseract/Leptonica primitives
behind an independent owned adapter, with no legacy globals or private sibling
code/state. Configure optional engine/decoder artifacts and language data through
trusted host configuration. Bind fingerprints to actual engine/decoder/data and
reader contract, check artifacts before/after extraction and preserve last-good
cache/evidence when configuration changes or work fails.

Deliver immutable image registration and bounded selected recognized-text reads,
then explicit PDF page OCR/rendering with original absolute page numbers. Declare
original raster coordinates and extracted text selectors without confusing them
with encoded byte offsets. Preserve original source/version identity, owner claims,
recognition method/confidence, partial coverage and OCR uncertainty. Generated
captions/summaries remain separate derived enrichment, never OCR literal text.

Bounds: original bytes1MiB; decoded raster at most4096 per axis and4Mi pixels;
recognized UTF-8 output64KiB; finite pages per request and explicit render pixel
budget. Validate header dimensions before decode/allocation, verify decoded
shape and reject excessive/invalid input. Tesseract recognition monitor polls
only the owning request's cancellation/deadline. Do not claim a hard process
teardown bound for library calls without owned helper qualification.

Native raster fixtures and actual OCR acceptance require no Python, JavaScript,
external image conversion or Agent/Inference/App. Check known raster sentinel,
selected UTF-8 bounds, original identity, confidence/coverage provenance, cache
reuse, foreign refusal, artifact/data change, unsupported/malformed/large raster,
active cancel/deadline, no partial cache, exact durable retries and survivors.
Qualify macOS and native ARM64 Linux with optional runtime/data explicitly
configured, full existing Sources regressions/PDF and independent releases.
Missing optional prerequisites fail OCR qualification, never count as passing.

## Remaining native failure boundary

Image and explicit PDF OCR are implemented; recognition/monitor/cache and owned
helper fault/lifecycle checks pass on both platforms. Native initialize/decode/
render calls now execute in a POSIX-spawned Sources helper with a bounded private
protocol. The parent owns its descriptor, child PID/group, deadline and teardown.
See native-worker-v1.md. Memory/descriptor/CPU/core setup and durable native
cancellation with cached/non-native peers now pass normal/sanitizer checks on
both platforms. Simultaneous native-peer acceptance passes macOS; Linux and
expanded corpus/full releases remain under qualification. Keep these invariants:
Do not fork a host's initialized SQLite/native runtime or share global cancellation.
The helper receives only original immutable input/render parameters and trusted
reader configuration, not database handles or private sibling state. Retain all
selected page results until success; parent validates bounded output and provenance
before cache publication. Native crash, malformed protocol, init/decode/render
stall, cancellation and expired deadline must discard new evidence and leave
healthy peers/old cache readable. Kill/reap only the owning helper; no orphan
processes or broad process-name kills. Qualify actual abort/stall/kill cases as
well as cooperative recognition monitors, and prove the release build omits
test-only events/fault injection. Service integration later must preserve this
ownership while bounding admitted workers/connections/queues and shutdown.

After helper qualification, expand native raster corpus (supported declared
formats, malformed/truncated inputs and oversized decoder allocations), finish
independent macOS/Linux releases with matching contents, and rerun affected
platform/failure/resource acceptance. The one-byte invalid model returning a
typed error does not prove all native model corruption is safe.

S17a does not close media acquisition, indexing/enrichment/Chutni, authenticated
bounded service or whole Sources resource/acceptance requirements. Full Sources
closure remains the priority before work resumes in other components.
