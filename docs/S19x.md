# S19x: bounded discovery, refresh and text-item recovery

Sources can extend an existing bound index job with files found by a later scan,
then capture those pending files through the existing immutable text pipeline.
A host-enabled runner also retries supported failed/skipped text items when a
scan observes a usable target. Successful historical indexed evidence remains
retained. This progresses C05/C06/C11/C13; it does not close those milestones or
release the complete Sources component.

## Public behavior

- index_discover(job_id, operation_id) performs one bounded directory scan and
  commits appended items, scan metadata and an exact receipt together. Retried
  receipts remain available without a live root grant.
- Job replies keep the original inventory coverage and expose checksum-validated
  latest_discovery: scan cycle, observed count and captured scan coverage.
- Host discovery_interval_ms (zero disables, otherwise100..60000ms) and CLI
  --discovery-interval-ms enable periodic refresh in --index-run.
- index_refresh_step performs at most one scan, one pending initial item and one
  queued recovery and one indexed-locator hash observation. Fair turns and
  cooldowns persist across restarts without
  growing client receipt history. Scan/initial/recovery are independent checkpoints.
- Failed/skipped supported text targets keep bounded identity-sensitive recovery
  rows. Unchanged scans preserve1..60s cooldowns; changed identities reset them.
  Successful recovery commits accepted evidence, intent removal and a recovery
  marker without rewinding the initial cursor.
- index_get exposes recovery_queue (pending count, highest failure level and
  earliest retry Unix milliseconds) and recovered_items_total. Retained queue
  health is readable offline and does not assert current file availability.
  Recovered/extended combined coverage remains conservative.

Bounds remain8 jobs,256 accumulated items/job,2048 recovery rows and at most8
refresh scheduler rows, plus the existing source/evidence/version/database limits.
Root/directory bindings and host controls are checked before acceptance.
See [the authoritative index contract](../contracts/index-v1.md).

## Qualification evidence

Native macOS/Linux gates cover later-file discovery and literal search, original
receipt retry, fewer observed files with historical items retained, owner isolation,
scan checksum corruption and accumulated item limits. Discovery transaction tests
pause after receipt preparation and exercise cancellation/deadline, actual SIGKILL,
root/directory replacement and subsequent retry.

The refresh fixture proves missing/healthy job progress, more than512 background
ticks without receipt growth, scheduler bounds, and a real CLI worker's initial
indexing, later new files, duplicate refusal, SIGKILL/restart, shutdown and offline
evidence. Recovery cases include returning missing files, corrected malformed
UTF-8 and a skipped directory becoming a text file; the original cursor and
successful evidence remain retained.

Recovery transaction tests pause after evidence update, intent removal and repair
marker insertion. Cancellation/deadline, actual SIGKILL and root/directory
replacement preserve the failed item, cursor and queued reservation. Later retry
succeeds. Offline public queue health is checked after each interruption. Invalid
failure metadata is refused before rendering a job or replacing a changed target.

Periodic observation transaction tests additionally stage history and derived
intent before cancellation/deadline, actual SIGKILL, file mutation/deletion or
root/directory replacement. The prior observation revision and immutable evidence
remain retained, with no new pending intent. A successful retry then accepts the
new indexed version. Signed locator revision overflow is refused. The shared
locator commit now physically revalidates after staging and before COMMIT.

Commands: make test-index-observation sanitize-index-observation;
make test-index-discovery sanitize-index-discovery;
make test-index-refresh sanitize-index-refresh;
make test-index-recovery sanitize-index-recovery. Standard test/sanitize include
these gates. Exact platform runs and logs are recorded in
[the rebuild verification record](../../../docs/ARCHITECTURE_REBUILD_VERIFICATION.md).
ASan/UBSan instrument owned component code and the tested runtime; bundled SQLite
remains uninstrumented. Commit-boundary cases are not an exhaustive filesystem
race/resource proof.

## Remaining work

Already indexed changed files now receive bounded periodic locator observations
and feed retained reindexing; snapshots and historical citations stay retained. Complete
watch/freshness lifecycle and policy, broader indexing readers/recovery, resource
and corruption/race qualification, acquisition, enrichment/Inference/Chutni,
authenticated bounded service and full independent release remain required.
No production legacy path was switched or removed by this checkpoint.
