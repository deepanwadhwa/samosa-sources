# S19i: atomic watch checkpoints

Public locator_watch_step verifies registered host/root and commits bounded locator
observations with one latest watch checkpoint in the same SQLite transaction.
Successful cycles do not consume durable locator operation-history capacity.
expected_cycle gates new work; retry of the immediately preceding cycle returns
its saved result offline, older/future cycles conflict. Watch get exposes the
latest checkpoint and stopped watches cannot perform new work.

Checkpoint digest, watch identifier and stored/published cycle must agree before
retrieval. Registration and checkpoint validation precede response publication,
so corruption returns one typed error. Existing per-chunk/precommit cancellation
and file/parent/root race checks protect atomic observation/checkpoint publication.

Native regression executes261 cycles, available-to-missing observations, exact
last-checkpoint retry offline, stale-cycle refusal, precommit cancellation with
cycle261 preserved, stopped refusal and corrupt-checkpoint typed single JSON.
Existing locator regressions remain required. Monitoring still reports not_running:
continuous runtime and shutdown/removal/reindex policy remain the next work.
